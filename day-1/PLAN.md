# Day 1 Plan — What Even IS a System?

> Written before I open anything. This is my intention for today.

---

## What I'm Trying to Figure Out

I've been writing software for 2 years and I've never stopped to ask:
*what is a "system" actually?*

I use the word constantly. "The system is down." "We need to design the system."
But if someone asked me to define it — really define it — I'd probably wave my hands
and say something vague. Today I'm fixing that.

---

## Goals for Today

- [ ] Write down MY definition of "system" before reading anything
- [ ] Read the intro material and update the definition
- [ ] Find 3 real systems I interact with daily and break them down
- [ ] Draw a request/response on paper — every single hop
- [ ] Write at least 10 lines of Go that makes the concept feel real

---

## What I Already Think I Know (Before Learning)

*Writing this before I start so I can see how wrong I am later.*

A system is... a bunch of components working together? Like a server that takes
requests and returns responses? I think it involves a database somewhere.
There's probably networking involved. And things can break.

That's genuinely all I've got. Let's go.

---

## Time Plan

- Read & take raw notes → `docs/notes.md`
- Build the Go thing → `src/main.go`
- Reflect → `docs/journal.md`
- Summarize → `README.md` (written last, after I actually know what happened)

---

## How I'll Know Today Was Worth It

If I can explain — out loud, to nobody, alone in my room like a weirdo —
what a system is, why it needs a database, and what happens when a single
request comes in... that's a win. That's Day 1 done.
